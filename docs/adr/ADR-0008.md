# ADR-0008 — Redis

## Context

O projeto prevê necessidades futuras de cache, coordenação e talvez filas auxiliares, mas ainda não quer tornar infraestrutura adicional obrigatória na Fase 0.

## Decision

Planejar Redis como componente futuro opcional, sem dependência obrigatória na fundação inicial.

## Consequences

### Positivas

- menor complexidade operacional inicial;
- mantém caminho claro para evolução de cache e coordenação;
- evita superengenharia precoce.

### Negativas

- algumas otimizações e execuções assíncronas ficam postergadas;
- certas evoluções futuras exigirão integração adicional depois.

## Alternatives

### Tornar Redis obrigatório desde o início

Aumentaria capacidade futura imediata, mas também custo de onboarding, deploy e troubleshooting.

### Não planejar Redis de forma alguma

Reduziria complexidade inicial, mas deixaria a arquitetura sem caminho explícito para evolução de escala e cache.
