# ADR-0002 — Repository Pattern

## Context

O projeto precisa impedir que views e serviços espalhem consultas ORM, filtros, anotações e detalhes de persistência, o que comprometeria testabilidade e clareza arquitetural.

## Decision

Adotar Repository Pattern para encapsular operações de persistência e consulta relevantes ao domínio.

## Consequences

### Positivas

- isolamento do ORM;
- serviços mais legíveis;
- consultas complexas concentradas;
- facilidade de testes por contrato.

### Negativas

- camada adicional;
- risco de repositories virarem wrappers triviais se usados sem critério.

## Alternatives

### ORM direto em services

Reduz código inicial, mas espalha persistência e aumenta acoplamento.

### Managers customizados apenas em models

Ajuda parcialmente, porém mantém dependência forte do modelo Django e não resolve toda a separação desejada.
